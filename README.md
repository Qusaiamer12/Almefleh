## شو بيعمل النظام

بضاعة بتدخل المستودع بحجم كبير (سطول) → بتطلع للمشغل → بترجع معبّأة بأحجام أصغر (جاطات)
→ بتتوزّع على الزباين بالدين → كل زبون إله كشف حساب أسبوعي.

```
توريد ١٠٠ سطل زيتون        →  ستوك السطول +١٠٠
إخراج ٢٠ سطل للمشغل        →  ستوك السطول −٢٠      (كمية بس، بدون فلوس)
إدخال ٢٠٠ جاط من المشغل    →  ستوك الجاطات +٢٠٠    (كمية بس، بدون فلوس)
بلال بيسحب ٥٠ جاط          →  ستوك الجاطات −٥٠  +  دين بلال += ٥٠ × سعر الجاط
بلال بيدفع ٥٠٠             →  دين بلال −= ٥٠٠      (مع تسجيل طريقة الدفع)
```

**المبدأ الأساسي بالتصميم:** الأرصدة (الستوك والديون) ما بتتخزّن كأرقام ثابتة —
بتنحسب من الحركات نفسها. يعني أي تعديل أو حذف لحركة قديمة بينعكس **فوراً وتلقائياً**
على كل التوتالات، رجوعاً وللأمام، بدون أي إعادة حساب يدوية.

## الحسابات والصلاحيات

| الصلاحية | قصي (أدمن) | عبود (مسجّل) | أبو بلال (اطّلاع) | الزباين الأربعة |
|---|:---:|:---:|:---:|:---:|
| تسجيل/تعديل/حذف حركات | ✅ | ✅ | ❌ | ❌ |
| رؤية الستوك والأرصدة والمبالغ | ✅ | ❌ | ✅ | رصيده هو بس |
| رؤية كشف كل الزباين | ✅ | ❌ | ✅ | كشفه هو بس |
| إدارة الأصناف والأسعار والمقادير | ✅ | يضيف صنف بدون سعر | ❌ | ❌ |
| رؤية/تعديل بيانات دخول أي حساب | ✅ | ❌ | ❌ | حسابه هو بس |
| رؤية سجل التدقيق | ✅ | ❌ | ❌ | ❌ |
| إرسال ملاحظة/طلب | — | — | — | ✅ |
| استقبال التنبيهات | ✅ | ✅ | ❌ | إسلام وعمار وسعد |

**شاشة عبود** مصمّمة للآيباد متل شاشة الكاشير: أصناف بالنص، بار حروف أبجدية عالجنب،
خانة بحث فوق، ولوحة أرقام للكمية. ما بيظهرله ولا رقم مالي.

## القواعد اللي النظام بيمشي عليها

**الستوك مركزي** — أي إخراج (لزبون أو للمشغل) بينخصم فوراً، وأي إدخال بيزيد.
النظام **ما بيمنع** السحب لما الكمية أكتر من المتوفر، بس بيطلّع **تنبيه كبير وواضح**
وبيسجّل الرصيد بالسالب.

**الأسعار بتاريخ سريان** — سعر واحد ثابت لكل صنف، بس مربوط بتاريخ "من متى صار ساري".
لما تغيّر سعر، النظام بيسألك من متى، والحركات من هذاك التاريخ وجاي بتتحدّث تلقائياً،
واللي قبله بتضل بسعرها القديم.

**السعر المعلّق** — الصنف اللي عبود بيضيفه بدون سعر: حركاته بتتسجّل بالكمية وبتضل بلا
مبلغ ("معلّق")، ولحظة ما تحدّد السعر بتنحسب كلها تلقائياً وبتدخل على دين الزبون.

**المقادير (BOM)** — لكل صنف جاهز وصفة بتحدد شو بده من مواد خام لكل وحدة.
لما يتغيّر سعر مادة خام، بيوصلك **اقتراح سعر** للأصناف المرتبطة فيها بيحافظ على
نفس هامش الربح: `السعر الجديد = السعر الحالي × (التكلفة الجديدة ÷ التكلفة القديمة)`.
إنت بتقرر: توافق، تعدّل الرقم، أو ترفض.

**تقرير الفاقد** — بيقارن المتوقّع حسب الوصفة مع الفعلي اللي رجع من المشغل.
إذا المادة الخام داخلة بأكتر من صنف، بتتوزّع عليهم بنسبة احتياج كل صنف.

**الأسبوع بيبلّش السبت** بتوقيت عمّان، وكل حركة بتاخد تاريخها ووقتها تلقائياً.
وأي تقرير بتقدر تطلّعه لأي فترة تحددها إنت (من تاريخ لتاريخ).

**سجل التدقيق** — كل إضافة وتعديل وحذف بينتسجّل: مين عملها، إمتى، شو كانت القيم قبل،
وشو صارت بعد. قصي بس بيشوفه.

**الكميات** — بتقدر تكتب بأرقام عربية أو إنجليزية، مع لواحق الوزن:
`١٠ك` = ١٠ كيلو، `٥٠٠غ` = نص كيلو، `١ك٥٠٠غ` = كيلو ونص.

## التشغيل محلياً

```bash
npm install
cp .env.example .env          # وعبّي القيم
npm run migrate               # إنشاء الجداول
npm run seed                  # الجهات والحسابات (زيد --demo لبيانات تجريبية)
npm start                     # http://localhost:3000
```

الحسابات الأوّلية بتطبع على الشاشة بعد `npm run seed`
(اليوزرات: `qusai`, `abood`, `abublal`, `blal`, `islam`, `ammar`, `saad`).

### الاختبارات

```bash
npm test                                                   # اختبارات المنطق
TEST_DATABASE_URL=postgresql://... npm test                # + اختبارات التكامل
```
⚠ اختبارات التكامل **بتمسح** محتويات القاعدة اللي بتشير إلها `TEST_DATABASE_URL`،
فلازم تكون قاعدة مخصّصة للاختبار.

## النشر (Render + Supabase — مجاناً)

**١) قاعدة البيانات على Supabase**
- أنشئ مشروع جديد → Project Settings → Database → انسخ الـ Connection string
- حطها بـ `DATABASE_URL` مع `DATABASE_SSL=true`

**٢) الاستضافة على Render**
- New → Web Service → اربط الريبو (الملف `render.yaml` جاهز)
- ضيف المتغيّرات السرّية من لوحة Render:
  `DATABASE_URL`, `SEED_ADMIN_PASSWORD`, `SEED_DEFAULT_PASSWORD`
  (`JWT_SECRET` و `CRED_KEY` بتتولّد تلقائياً)
- بعد أول نشر، شغّل من الـ Shell: `npm run migrate && npm run seed`

**٣) منع سكون الخدمة — UptimeRobot**
- أنشئ مونيتور من نوع HTTP(s) على `https://<your-app>.onrender.com/api/health`
- الفاصل: كل ٥ دقايق. هيك Render ما بتنام وSupabase ما بتتوقف من الخمول.

**٤) النسخ الاحتياطي على جوجل درايف**
```bash
node scripts/gdrive-setup.js <CLIENT_ID> <CLIENT_SECRET>
```
بيعطيك `GDRIVE_REFRESH_TOKEN` — حطه مع `GDRIVE_FOLDER_ID` بمتغيّرات Render.
النظام بياخد نسخة **كل ساعة** وبيرفعها على الفولدر. بدون هالإعدادات بتضل النسخة
محلية بس (وقرص Render مؤقّت، فالرفع مهم).

نسخة يدوية بأي وقت: `npm run backup`

## بنية المشروع

```
db/schema.sql          مخطط قاعدة البيانات + الـ views اللي بتحسب الأرصدة
src/
  lib/
    quantity.js        تحليل "١٠ك" و "٥٠٠غ" وتحويل الأرقام العربية
    dates.js           الأسبوع بيبلّش السبت، بتوقيت عمّان
    period.js          فترة التقرير: أسبوعية أو مخصّصة
    pricing.js         السعر الساري، تكلفة المقادير، اقتراحات تعديل السعر
    crypto.js          bcrypt للدخول + تشفير قابل للفك عشان الأدمن يشوف الباسوردات
    audit.js           سجل التدقيق (قبل/بعد)
    notify.js          التنبيهات الهادئة
  routes/              الواجهة البرمجية
  jobs/backup.js       النسخ الاحتياطي ورفعه على جوجل درايف
public/                الواجهة (HTML/CSS/JS بدون أي build)
test/                  ٤٠ اختبار: المنطق + التكامل
```

## ملاحظة أمنية

حسب المتطلّبات، **قصي بيقدر يشوف كلمات سر كل الحسابات** حتى بعد ما يغيّروها.
عشان هيك النظام بيخزّن نسخة مشفّرة (AES-256-GCM) من كل كلمة سر جنب الـ bcrypt hash.
يعني اللي بيوصل على `CRED_KEY` + قاعدة البيانات بيقدر يقرأ كل كلمات السر.
خلّي `CRED_KEY` سرّي ومختلف عن `JWT_SECRET`، ولا تستعملوا كلمات سر مكرّرة من حسابات تانية.
